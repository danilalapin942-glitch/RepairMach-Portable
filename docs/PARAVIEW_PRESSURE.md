# Распределение давления по точкам

RepairMach автоматически сохраняет отдельные папки для каждой стационарной точки VSPAERO:

`06_vspaero_results/runs/<run>/paraview/0001_M0p4_A0_B0/`

Такие же папки создаются внутри опорных проб сертификатора и численных повторов.
После переэкспорта старого диагностического запуска папка называется `paraview_surface`.

- `pressure.vtu`: физические поверхности, собственные координаты и исходные значения без сглаживания.
- `wake.vtu`: отдельно вынесенный след с нулевыми SurfaceID/ComponentID; раскраска Gamma. Его нулевой Cp не является давлением на самолёте.
- `point.json`: M, alpha, beta, статус приёмки решателем, качество, hashes и смысл полей.
- Родительские `manifest.json` и `README.md`: полный список точек и инструкция.

Открытие: **ParaView → File → Open → pressure.vtu → Apply**. Выбрать Cell Data → `Cp_or_DeltaCp`.
На тонкой несущей поверхности это **перепад ΔCp**, на толстом теле — **Cp**.
Это безразмерные величины, не давление в Па. Поля не содержат полуэмпирического вязкого сопротивления.
Состав поверхностей определяется фактической постановкой: например, `lifting` содержит крыло и оперение, а не давление на всём самолёте.

`SolverAccepted=0` / `diagnostic_not_accepted` означает, что поле можно рассматривать лишь для диагностики.
`SolverAccepted=1` подтверждает только проверку конкретного запуска решателя; это не сертификат всей АДХ.
Наличие файла само по себе ничего не говорит о сходимости. Экспорт не меняет исходный вердикт.

VTU содержит все данные внутри себя; ADB или исходная модель для открытия не нужны.
`OriginalCellID` хранит нулевой индекс треугольника исходного ADB для аудита.
Оси и единицы длины сохраняются как в решателе. Никакого неявного поворота координат нет.

Для MachLine в `05_machline_results/paraview/<point>/` копируется исходный body VTK вместе с журналом,
результатами и, если применимо, маской сил. Законы Cp не смешиваются и не переименовываются.
Численное замыкание может присутствовать в поле, но не участвовать в силах: проверяйте приложенную маску.

## Поддержка и проверка формата

Поддержан стационарный ADB v3, включая многоточечные серии, оба порядка байтов, записи роторов/сопел,
контрольных поверхностей и следа. Неизвестный формат, неполный файл, нечисловое поле или несогласованные
с POLAR режимы записываются как ошибка экспорта. Вместо них поле не синтезируется.
Нестационарный ADB требует отдельного временного экспортера и сейчас отклоняется явно.

Формат проверен по [официальному исходному коду OpenVSP 3.51.0](https://github.com/OpenVSP/OpenVSP/blob/OpenVSP_3.51.0/src/vsp_aero/Solver/VSP_Solver.C)
(`WriteOutAerothermalDatabaseHeader/Geometry/Solution`) и реальным ADB.
Контрольное открытие выполнялось в установленном ParaView 6.1.1.

## Численная перепроверка отклонённой опоры

Пункт **[9] → [16]** читает ранее созданный `certificate.json`, проверяет hashes MASTER,
сеточных двойников, свидетельств и решателей и повторяет **одну уже проверявшуюся опору**.
Применяются штатная сеточная лестница и общий механизм численного восстановления:

1. Исходная проба с исходными настройками.
2. При отказе исключительно по невязке — существующий усиленный режим и два независимых повтора.
3. Если этого мало — ограниченная дополнительная ступень: NCPU=1, GMRES factor=0.01,
   WakeNumIter=64, NumWakeNodes=24, WakeRelax=0.3. Оба повтора обязаны пройти прежние пределы.
4. Для мелкой сетки — дополнительный расчёт с не менее чем 96 итерациями следа и сравнение коэффициентов.

Геометрия, Sets, опоры, положение ГО и допуски приёмки не меняются. NaN, ошибки геометрии,
несоответствие режима и отсутствующие файлы не обходятся численной лестницей.
Сценарий не выдаёт сертификат, не снимает FAIL, не запускает MachLine и не меняет `latest_certificate.json`.
Межсеточное сравнение — штатный индикатор устойчивости, не оценка GCI и не экспериментальная ошибка.
