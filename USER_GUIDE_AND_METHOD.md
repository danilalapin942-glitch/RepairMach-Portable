# RepairMach 9.1: руководство оператора и полная методика расчёта

> При сертификации VSPAERO контролируются и средняя, и максимальная локальная невязка. Если отказ связан только с невязкой, программа сама выполняет два строгих однопоточных повтора. Исходный отказ сохраняется в отчёте, а допуск выдаётся лишь при повторяемости результатов и неизменной сеточной сходимости.

## 1. Назначение и принцип работы

RepairMach объединяет четыре расчётных источника:

- OpenVSP/VSPAERO — подъёмная сила, `Cyα`, индуктивное сопротивление и
  моменты;
- MachLine — давление и волновое сопротивление на сверхзвуке;
- OpenVSP Parasite Drag — дозвуковое вязкое/паразитное сопротивление;
- заранее объявленная полуэмпирика — вклад антенн, щелей, пилонов и иных
  деталей, которые не разрешены выбранными численными моделями.

Цель комплекса — выпустить воспроизводимый прогноз АДХ нового самолёта без
использования его продувки или книжной кривой при выборе геометрии, сетки,
решения и поправок.

Методика последовательно отвечает на четыре разных вопроса:

1. пригодна ли конкретная геометрия для конкретного backend;
2. получено ли полное конечное и численно устойчивое решение;
3. собраны ли физические слагаемые без пропусков и двойного учёта;
4. как запечатанный прогноз согласуется с независимым эталоном.

Сертификат геометрии отвечает на первый вопрос и выполняет квалификационную
сеточную проверку. Он не является сертификатом аэродинамической точности.

## 2. Установка и первый запуск

1. Поместите комплекс в короткий каталог, например
   `C:\RepairMach-Portable`.
2. Запустите `RepairMach.bat`.
3. Выберите `[1] Проверить среду`.
4. Убедитесь, что программа нашла:

   - переносимый Python;
   - `engines\MachLine\machline.exe`;
   - `vspscript.exe` и `vspaero.exe` одной установки OpenVSP;
   - Node.js и `@oai/artifact-tool` для Excel.

5. Создайте проект `[2]` или выберите существующий `[3]`.
6. После изменения путей или переноса комплекса снова выполните `[1]`.

Основные функции:

| Пункт | Действие |
|---:|---|
| `[4]`, `[5]` | импорт и диагностика TRI |
| `[6]`, `[7]` | создание JSON и запуск MachLine |
| `[8]` | ручной, явно несертифицированный диапазон VSPAERO |
| `[9]` | готовые сценарии и сертификация |
| `[10]` | дозвуковой Parasite Drag |
| `[11]` | гибридная сборка и Excel |
| `[12]` | открыть текущий проект |
| `[13]` | ручной запуск `.vspscript` |
| `[14]` | слепая верификация |

Внутри списка `[9]` сценарий `[13]` — «Автоматическая сертификация
геометрии VSP3». Пункт `[13]` главного меню имеет другое назначение.

## 3. Паспорт самолёта и опорные величины

При создании проекта задаются:

- `Sref` — опорная площадь;
- `cref` — САХ либо другая документированная продольная опорная длина;
- `bref` — размах либо другая документированная поперечная длина;
- `CG X Y Z` — центр масс в системе координат модели.

Единицы должны совпадать с единицами VSP3. Ошибка `Sref` масштабирует
коэффициенты сил; ошибки `cref` и CG непосредственно искажают коэффициенты
моментов. Для каждой величины сохраните источник: чертёж, техническое описание
или документированный расчёт планформы.

Не переносите опоры с другого самолёта. Перед первым расчётом откройте
`projects\<имя>\project_config.json` и перепроверьте значения. При наличии
действующего сертификата стандартный сценарий VSPAERO берёт опоры из него и не
позволяет незаметно заменить их во время запуска.

## 4. Подготовка MASTER в OpenVSP

### 4.1. Имена компонентов

Закреплены базовые имена:

| Деталь | Имя | Роль |
|---|---|---|
| крыло | `Wing` | тонкая несущая поверхность |
| фюзеляж | `Fuselage` | толстое тело |
| горизонтальное оперение | `GO` | тонкая несущая поверхность |
| вертикальное оперение | `VO` | тонкая несущая поверхность |
| мотогондола | `Gondola` | толстое тело |

`Wing` и `Fuselage` должны присутствовать ровно по одному разу. Повторные
детали получают суффикс: `VO_upper`, `VO_lower`, `Gondola_L`, `Gondola_R`.
Неизвестное имя не угадывается. Историческое имя допускается только через
единственный точный alias, записанный до сертификации.

### 4.2. Наборы OpenVSP

- пользовательский `Set_1` — `Fuselage`, `Gondola*` и другие объявленные
  толстые тела;
- пользовательский `Set_2` — `Wing`, `GO*`, `VO*`, причём тонкая деталь
  должна иметь тип OpenVSP `Wing`.

В API OpenVSP эти наборы имеют индексы 4 и 5. Деталь не должна быть сразу в
обоих Sets. Сертификация может исправить только однозначную ошибку назначения
в расчётном двойнике; неоднозначный состав блокирует процесс.

### 4.3. MASTER и расчётные двойники

Выберите окончательную VSP3 и считайте её MASTER. После запуска сертификации
не изменяйте этот файл. Изменение площади, удлинения, стреловидности, профиля,
положения агрегатов, входа гондолы или формы фюзеляжа создаёт новый MASTER и
требует нового сертификата.

RepairMach не правит MASTER. Небольшая техническая регуляризация выполняется
только в независимых двойниках и никогда не переносится между решателями.

## 5. Настройка сертификации проекта

Базовая политика хранится в `config\geometry_certification.json`. Проектные
изменения задаются в `project_config.json`:

```json
{
  "geometry_certification": {
    "policy_overrides": {
      "semantics": {
        "aliases": {
          "VentralVO": "VO"
        },
        "declared_exclusions": [
          {
            "component": "AuxiliaryBody",
            "backends": ["vspaero", "hybrid"],
            "reason": "служебная референсная поверхность, не часть самолёта",
            "replacement_required": ["not_physical"]
          }
        ]
      }
    },
    "scope_override": null,
    "tri_path": null,
    "run_vspaero_probes": true
  }
}
```

Контракт исключения в версии 1 строгий:

- `component` — непустое точное имя, существующее ровно один раз;
- `backends` — ровно `['vspaero', 'hybrid']` в указанном порядке;
- `reason` — непустая инженерная причина;
- `replacement_required` — непустой список канонических значений:
  `machline_pressure_wave_all_points`, `parasite_drag_subsonic` или
  единственный `not_physical`.

`not_physical` нельзя смешивать с физическими источниками. Исключение не
добавляют после просмотра эталона. Старое поле `backend`, строка вместо списка,
повторы, другое написание или отсутствующий компонент блокируют политику.

Параметр `tri_path` оставлен как необязательная историческая подсказка. Он не
может подменить геометрию MachLine: при доступном MachLine сертификация сама
экспортирует новый TRI из Fine-двойника OpenVSP через NASCART и связывает всю
цепочку SHA-256.

## 6. Сертификация G0–G8

Запуск: `[9]` → `[13] Автоматическая сертификация геометрии VSP3`.

### G0 — регистрация

Фиксируются обычный и канонический SHA-256 MASTER, размер файла, `Sref`,
`cref`, `bref`, CG, область `Mach–alpha–beta`, политика и их отпечатки.
Создаётся `frozen_master.vsp3`. В конце исходный SHA-256 проверяется повторно.

### G1 — инвентаризация и семантический аудит

OpenVSP перечитывает все геометрии, точные имена, типы, Sets, параметры
секций и границы. Проверяются обязательные детали, суффиксы, aliases и явные
исключения. Неизвестная или неоднозначная роль является blocker.

### G2 — нативная диагностика

Сохраняется исходное состояние без исправлений. Недоступная через VSP3
метрика записывается как `null`, а не заменяется предположением.

### G3 — запечатанный PLAN

До изменения любой копии строится полный детерминированный план. Он связан с
SHA-256 MASTER, политики, опор и области. Несовпадение любой привязки запрещает
APPLY.

### G4 — независимые двойники

Создаются:

- `vspaero_mixed` — тонкие и толстые поверхности;
- `vspaero_lifting` — только несущие поверхности с отдельным пустым thick-Set;
- `machline` — источник поверхности для MachLine;
- `parasite` — неизменённая полная копия для Parasite Drag.

### G5 — контролируемая регуляризация

Разрешены только действия из запечатанного PLAN:

- однозначное назначение `Set_1`/`Set_2`;
- удаление заранее объявленного исключения из расчётных Sets;
- малая конечная хорда вместо практически нулевой законцовки;
- заранее заданный offset точного компонента по точной оси.

По умолчанию изменение площади ограничено 1%, перемещение — `0,002·cref`.
Произвольное закрытие отверстий, изменение формы или подгонка не выполняются.

### G6 — повторное чтение

Каждый двойник снова открывается OpenVSP. Фактические значения параметров,
состав и геометрические отпечатки сравниваются с планом и бюджетом. Ошибка
записи или повторного чтения блокирует соответствующий тракт.

### G7 — сеточная квалификация и TRI

Для mixed VSPAERO, lifting VSPAERO и MachLine создаются обязательные уровни
`Coarse`, `Medium`, `Fine`. Для пограничной точки автоматически добавляются
проверочные `ExtraFine` и, только при сохраняющейся значимой осцилляции внутри
допусков, `UltraFine`. Все шесть фактически потребляемых Tess-параметров
должны строго возрастать и после записи совпадать с политикой; одинаковые
фактические подписи уровней запрещены.

Полный профиль `full_anchor_envelope` содержит 15 anchors:

| Mach | Углы alpha |
|---:|---|
| 0,0 | 0°, 5° |
| 0,4 | 0°, 5° |
| 0,8 | 0°, 1°, 5° |
| 1,2 | 0°, 1°, 5° |
| 1,7 | 0°, 1°, 5° |
| 2,2 | 0°, 5° |

Каждый anchor непосредственно рассчитывается как минимум на трёх уровнях. Для
каждого результата обязательны:

- ровно одна запрошенная пара Mach/alpha без пропуска и лишней строки;
- конечные `Mach`, `AoA`, `CLtot`, `CDi`, `CDtot`;
- завершённый и непротиворечивый Set-контроль;
- отсутствие timeout, NaN в итоговых величинах, upwind-loop и fatal-сигналов;
- при `M > 0` — однозначная запись невязки и `log10(L2) <= -0.3`; при
  строго `M=0`, где VSPAERO 3.51 её не печатает, — полный сеточный
  контроль без иных ошибок;
- сходимость `CLtot` и `CDtot` последней принятой пары: относительное отличие не более 5%
  или абсолютное отличие не более `0,005` для `CLtot` и `0,0005` для
  `CDtot`;
- отсутствие значимой осцилляции последней принятой тройки. Программа сохраняет знаковые
  `coarse_medium_delta` и `medium_fine_delta`, признаки `monotonic` и
  `oscillating`, а также `contraction_ratio`. Смена знака двух значимых шагов
  вызывает следующий проверочный уровень; изменение меньше 10% абсолютного
  допуска считается шумом ниже разрешения. Большая величина первого шага без
  смены знака сама по себе не является veto. Пределы 5%, 0,005 и 0,0005 не
  ослабляются. `Fine` остаётся производственной сеткой.

Для `alpha=beta=0`, точного `CLtot=0` и конечной итоговой невязки VSPAERO
допускается узкое предупреждение `zero_rhs_normalization_nan` о промежуточной
нормировке нулевой правой части. Оно не разрешает NaN в коэффициентах или
отсутствующую итоговую невязку.

Если lifting-точка даёт настоящий нечисловой отказ, программа автоматически
повторяет только её на диагностических двойниках без одной семантической
группы. Восстановившая решение группа записывается в `failure_diagnostics`.
Такой двойник не получает допуск: оператор исправляет соответствующие
компоненты или сопряжения в MASTER и запускает новую сертификацию.

При наличии `Gondola*` сверхзвуковые anchors с `engine_boundary: auto`
получают `To Face` для всех распознанных гондол. Без гондолы сохраняется
`model`. Угол GO и `beta` входят в область квалификации.

Если mixed не проходит, программа может проверить lifting-only. Такой успех
не считается полной геометрией: толстые тела получают явные исключения, а
последующий гибрид обязан восстановить их давление/волну для всех точек и
Parasite Drag для всех дозвуковых Mach.

Для MachLine программа экспортирует NASCART TRI именно из Fine-двойника. В
манифесте фиксируется цепочка
`MASTER → PLAN → base twin → Fine twin → TRI`, включая Set-индексы, параметры
сетки, путь и SHA-256 `vspscript.exe`. Произвольный внешний TRI или изменение
любого звена цепи отклоняется до чтения сетки. После этого проверяются индексы,
повторные/вырожденные панели, неманифолдные рёбра, нормали и Mach-критерий.
Консервативный ремонт ограничен меньшим из 100 панелей и 0,5%; автоматическое
смещение вершин выключено.

### G8 — сертификат

Выдаются `certificate.json` и `certificate.md`, а также указатель
`latest_certificate.json`. Неудачный запуск записывается через
`latest_failed_certificate.json` и не заменяет последний действующий.

Вердикты:

- `PASS_NATIVE` — полная mixed-геометрия прошла без регуляризации;
- `PASS_REGULARIZED` — полная mixed-геометрия прошла после разрешённых малых
  изменений двойника;
- `PASS_WITH_DECLARED_EXCLUSIONS` — пригоден ограниченный тракт, а гибридное
  восстановление обязательно;
- `FAIL` — сертификат использовать нельзя.

Всегда проверяйте отдельно:

- `backends.vspaero/machline/parasite_drag/hybrid`;
- `eligible` или `conditional` нужного backend;
- `qualified_scope` и `eligible_scenarios`;
- `scenario_eligibility.<id>.scenario_sha256` полного канонического сценария;
- `solver_geometry.path` и `sha256`;
- флаги `full_geometry_represented`, `hybrid_substitution_required` и
  `master_unchanged`;
- целостность сертификата и SHA-256 записанных исполняемых файлов.

## 7. Расчёт после сертификации

### 7.1. Контроль `Cyα`

Начните с `[9]` → `[6] Контроль Cyα — фиксированное ГО 0°`. Он рассчитывает
`M=0,8; 1,2; 1,7` и прямые углы `alpha=0°/1°`. Производная:

```text
Cyα(M) = [Cy(M, 1°) - Cy(M, 0°)] / 1°.
```

Пропущенную точку нельзя заменять интерполяцией. Сверхзвуковые углы решаются
независимо; для гондол применяется `To Face`.

### 7.2. Серия VSPAERO

После контрольного допуска используйте дозвуковую, сверхзвуковую или
`[8] Полную АДХ — фиксированное ГО 0°`. Если `latest_certificate.json`
относится к выбранному MASTER, RepairMach:

1. проверяет целостность сертификата, область, ID сценария и SHA-256 его
   актуального полного словаря;
2. останавливается, если сертификат этого MASTER не допускает запуск;
3. автоматически выбирает записанный Fine-двойник mixed/lifting;
4. блокирует опорные величины значениями сертификата;
5. записывает в манифест SHA-256 MASTER, двойника, POLAR, CSV, лога, скрипта,
   `vspscript.exe` и `vspaero.exe`.

В этой фразе `[8] Полная АДХ` означает сценарий № 8 внутри меню `[9]`, а не
пункт `[8]` главного меню. Сценарный словарь запечатывается целиком. Если под
тем же ID изменились cases, GO, beta, `engine_boundary`, solver controls или
иное поле, проверка действует fail-closed и требует новой сертификации.

Пункт `[8]` главного меню допускает произвольный интерактивный диапазон. Он
намеренно выполняется на выбранном MASTER без `certificate_binding` и печатает
метку `НЕСЕРТИФИЦИРОВАННЫЙ ЗАПУСК`. Такой результат полезен для разведочного
расчёта, но не является продолжением сертифицированной цепочки.

VSPAERO служит источником `Cy=CLtot`, `CDi`, моментов и прямого `Cyα`.
Строгая проверка требует полного заявленного диапазона Mach/alpha, конечных
коэффициентов и `log10(L2) <= -0.3` для каждой точки. `GO=0°` — фиксированный
геометрический угол, а не автоматическая балансировка по `Cm=0`.

Гибрид не принимает заявленную producer-оценку на веру: он повторно проверяет
фактические POLAR и log. Значение `max_log10_l2_residual` в манифесте может
быть строже `-0.3`; значение выше `-0.3` не ослабляет абсолютный предел
RepairMach, поскольку используется более строгий из двух порогов.

Диапазон `M=0,9…1,1` исключён из стандартной полной серии. Для него нужны
методы, способные описать реальную транзвуковую структуру, вязко-ударное
взаимодействие и отрыв.

### 7.3. MachLine

Используйте `[6]` и `[7]` только с `certified_mesh.tri`, записанным в
`backends.machline.solver_geometry`. Для каждой пары Mach/alpha должны
совпадать TRI, опоры, CG, поток, оси и состояние следа.

Сертификатор создаёт два разных, но связанных артефакта:

- `certified_audit_mesh.tri` содержит толстые поверхности и тонкие
  `Wing/GO/VO`; он нужен для проверки полноты состава, топологии и
  сверхзвукового Mach-критерия во всей заявленной области;
- `certified_mesh.tri` содержит водонепроницаемое толстое тело и, если это
  необходимо, отдельное заострённое численное кормовое замыкание. Только этот
  файл разрешён как вход MachLine.

Тонкие несущие поверхности не теряются: их нагрузки, `Cy`, `CDi`, моменты и
`Cyα` рассчитывает VSPAERO. MachLine отвечает за маскированный вклад давления
и волнового сопротивления толстого тела. Это осознанное разделение физики, а
не две конкурирующие оценки одной силы.

Рядом с разрешённым TRI обязательно лежит `force_integration_mask.json`.
RepairMach распознаёт его автоматически, проверяет SHA-256 TRI и полный охват
компонентов, применяет оси NASCART `X,Z,-Y`, преобразует CG, включает
`neumann-doublet-only-mass-flux`, `GMRES/DIAG`, строгую невязку и отключает
след. Нельзя переносить один TRI без его маски или редактировать любой из этих
файлов.

Если сертификатор построил кормовое замыкание, оно участвует в решении
потенциала, но исключается из физической суммы по cell-vector `dC_f`.
RepairMach сначала доказывает совпадение полной суммы `dC_f` с
`total_forces` MachLine и только затем применяет маску. Такой результат нельзя
выдавать за полный `Cx`: донное сопротивление обязано поступить из заранее
объявленного полуэмпирического слагаемого гибридной методики.

Успешный запуск создаёт манифест `repairmach.machline-run/1.0`, который
фиксирует MachLine executable, входной JSON, TRI, report, log и их SHA-256.
Принимается только явный `solver_status_code=0`, конечные `residual.norm` и
`residual.max` и конечные коэффициенты в скоростных осях. Для
сертифицированного двойника действуют абсолютные пределы
`residual.norm <= 0.05`, `residual.max <= 0.01`; дополнительно проверяются
совпадение VTK/TRI и отсутствие недопустимой боковой силы при `beta=0`.

Если к MachLine добавляется `VSPAERO CDi`, активный след MachLine по умолчанию
запрещён из-за риска двойного учёта индуктивного сопротивления.

### 7.4. OpenVSP Parasite Drag

Пункт `[10]` применим только при `0 < M < 1`. При действующем сертификате
выбирается отдельный неизменённый Parasite-двойник. Для каждого нужного
дозвукового Mach выполните отдельный расчёт.

Результат принимается только при непустом компонентном составе, конечных
неотрицательных `CD`, совпадении возвращённых Mach и `Sref` с заданием и целом
манифесте. Манифест фиксирует MASTER, двойник, Set, условия, CSV, log,
script, `vspscript.exe` и SHA-256 всех этих файлов, после чего получает
`record_fingerprint`. Гибрид повторно хэширует фактические файлы, читает
ReadVSPFile, GeomSet, Mach, Sref и путь CSV непосредственно из script и
сравнивает реальный solver VSP3 с сертификатом. Подмена либо простое
переименование model/Set/script/log/CSV/manifest действует fail-closed.

### 7.5. Полуэмпирические слагаемые

Политика `config\hybrid_method.json` содержит `semiempirical_terms`. Для
каждого включённого члена до раскрытия эталона задаются:

- уникальный `id` и физическое назначение;
- независимый источник и версия зависимости;
- диапазон Mach;
- модель и нормировка;
- запрет экстраполяции.

Штатный `external_details` выключен и равен нулю. Его нельзя включить или
подобрать по близости к кривой проверяемого самолёта. Полуэмпирика допустима
как переносимая физическая модель для неразрешённых деталей, а не как
поточечный коэффициент подгонки.

## 8. Автоматическая гибридная сборка

Запуск: `[11] Автоматический гибридный расчёт и Excel с графиками`.

Оператор указывает манифест исследования VSPAERO, каталог отчётов MachLine,
каталог манифестов Parasite Drag, гибридную политику и сертификат. Для
недиректной методики `Cyα` дополнительно указывается тонкостенная серия.

Базовая формула:

```text
Cx_total = Cx_pressure_wave(MachLine, wind-axis CD)
         + Cx_induced(VSPAERO CDi)
         + Cx_viscous(OpenVSP Parasite Drag, M < 1)
         + Cx_semiempirical,

Cy       = VSPAERO CLtot.
```

Сопоставление выполняется по точным Mach/alpha с допусками политики. Гибридный
сборщик проверяет:

- сертификат, backend, область, опоры, GO, `beta` и граничную постановку;
- совпадение SHA-256 MASTER и каждого расчётного двойника;
- фактические SHA-256 исполняемых файлов с сертификатом;
- SHA-256 POLAR/CSV/report/log и повторную проверку качества выходов;
- состояние решателей, невязки и конечность коэффициентов;
- наличие ровно одного источника каждой точки;
- отсутствие транзвуковых точек в запрещённом интервале;
- отсутствие двойного учёта wake/`CDi`;
- область каждого полуэмпирического члена.

При исключениях `replacement_coverage="auto"` строится только из реально
использованных и запечатанных источников. Для физического компонента MachLine
обязан покрыть каждую строку Mach/alpha, а Parasite Drag — каждый дозвуковой
Mach. Для `not_physical` сертификат должен явно содержать такой единственный
маркер. Голый POLAR, голый Parasite CSV, отчёт MachLine без манифеста,
изменённый файл или источник другого самолёта не образуют строгий пакет.

Результат со статусом `incomplete` не публикуется как готовая АДХ.

## 9. Excel и контроль книги

В `08_hybrid_results\hybrid_<дата>` создаются:

- `hybrid_result.json` — полный результат и происхождение;
- `hybrid_points.csv` — все точки и отдельные слагаемые;
- `hybrid_cy_alpha.csv` — прямой и итоговый `Cyα`;
- `RepairMach_hybrid_results.xlsx`;
- `workbook_verification.json`;
- PNG-превью листов.

Книга содержит листы `Сводка`, `АДХ`, `Cyα`, `Полуэмпирика`, `Источники` и
`Методика`. Диаграммы `Cx0(M)`, `Cy(M)` и `Cyα(M)` являются scatter-графиками
с числовой осью Mach и получают X/Y только из ячеек этой же книги.

Сборка fail-closed: формульная ошибка, внешняя формульная ссылка, внешний
chart reference, неверный тип/ось графика или внешняя часть XLSX прекращают
публикацию; повреждённый файл удаляется. Принимайте книгу только когда
`workbook_verification.json` имеет `build_status: passed`, нулевое число
формульных ошибок и `external_links_detected: false`. После этого визуально
просмотрите все PNG: подписи, масштабы, легенды, пропуски и выбросы.

## 10. Критерии качества и погрешности

До просмотра эталона проверяются:

- полные пары и сетки условий;
- конечность коэффициентов;
- статусы и невязки решателей;
- локальная гладкость по Mach и alpha там, где она физически ожидается;
- сеточная сходимость и устойчивость к малым техническим offsets;
- физическая полнота гибридной суммы;
- отсутствие подстройки по эталону.

Согласованные уровни:

- 5% — численный предел последней принятой пары либо локальной численной
  проверки при обязательном отсутствии значимой осцилляции;
- 11% — ориентир средней суммарной ошибки после независимого раскрытия;
- 15% — целевой коридор отдельной точки;
- 20% — жёсткий предел отдельной точки;
- 5% по модулю — предел среднего знакового смещения.

Пять процентов численной ошибки не означают пять процентов относительно
продувки. В суммарную неопределённость входят геометрия, опоры, шероховатость,
зазоры, вязкость, отрыв, вязко-ударное взаимодействие и структура скачков.
Минимизация ошибки на одной геометрически несовершенной модели способна
ухудшить переносимость методики.

Если после раскрытия обнаружена ошибка, сначала классифицируйте причину:
геометрия, постановка, сетка, численный сбой, пропущенная физика или ошибочный
эталон. Исправленный метод выпускается как новая версия и заново проверяется
на другом самолёте; старый прогноз не переписывается.

## 11. Слепая независимая проверка

До получения эталона:

1. завершите и заморозьте MASTER;
2. сертифицируйте его и проверьте нужные backend/сценарий;
3. выберите расчётную и гибридную политики;
4. в `[14]` создайте входной слепой пакет;
5. сохраните отпечаток `blind_manifest.json`;
6. выполните VSPAERO, MachLine и Parasite Drag;
7. соберите JSON/CSV/XLSX пунктом `[11]`;
8. в `[14]` запечатайте все файлы прогноза и проверьте
   `prediction_seal.json`;
9. только после этого подключайте эталон;
10. сравнивайте без изменения запечатанного прогноза.

Повторить несошедшуюся точку можно только по процедуре, объявленной до
раскрытия. Изменение геометрии, политики или решателя после печати требует
нового пакета. Подробности — в `BLIND_VALIDATION.md`.

## 12. Типовые остановки

| Сообщение или симптом | Действие |
|---|---|
| неизвестное/повторное имя | исправить MASTER или объявить один точный alias |
| исключение не соответствует ровно одной детали | исправить точное имя; не ослаблять правило |
| неверные Sets | проверить роли; разрешить только однозначную правку двойника |
| нулевая законцовка превышает бюджет | инженерно исправить MASTER и создать новую версию |
| Fine-двойник не совпадает с PLAN | не использовать результат; повторить сертификацию |
| `GEO-TRI-LINEAGE-001` | использовать автоматический TRI текущего Fine-двойника |
| topology/Mach criterion blocker | перестроить исходную геометрию или сеточную политику |
| нет одной из 15 сеточных троек | повторить соответствующий anchor; сертификат не расширять |
| `log10(L2) > -0.3` | считать точку несошедшейся; проверить сетку и постановку |
| Medium→Fine погранично не проходит | дождаться автоматического ExtraFine/UltraFine; не менять допуск |
| Последняя тройка сохраняет значимую смену знака | исправить сетку и постановку; шум ниже 10% абсолютного допуска учитывается отдельно |
| `failure_diagnostics` восстанавливает решение без группы | исправить эту группу или её сопряжения в MASTER; диагностический двойник не выпускать |
| mixed не проходит, lifting проходит | проверить толстые тела; принять только с полным замещением |
| сертификат этого MASTER не допускает сценарий | повторить сертификацию с нужной областью |
| сценарий с прежним ID изменён | вернуть точный запечатанный словарь или пересертифицировать новую постановку |
| ручной `[8]` помечен несертифицированным | для выпуска повторить постановку готовым неизменённым сценарием `[9]` |
| MachLine report без sidecar manifest | повторить запуск через RepairMach `[7]` |
| голый Parasite CSV | повторить `[10]`, использовать JSON-манифест |
| дозвуковая точка без Parasite Drag | рассчитать тот же Mach и пересобрать пакет |
| активный MachLine wake + `VSPAERO CDi` | изменить заранее выбранную постановку; не обходить блокировку |
| Excel не прошёл verification | исправить источник и пересобрать; не публиковать XLSX вручную |
| MASTER или solver изменился | новый сертификат и новый слепой пакет |

  `log10(L2) <= -0.3`, а при `M=0` прошли трёхсеточный контроль.
