# Автоматическая сертификация геометрии RepairMach 9.1

## Назначение

Методика `RM91-GEOMETRY-CERT-1` отвечает на вопрос: можно ли воспроизводимо
использовать точный MASTER с указанными опорами, решателями, сеточной
политикой и областью `Mach–alpha–beta`.

Сертификат подтверждает происхождение геометрии, ограниченность изменений,
сеточную квалификацию и пригодность каждого backend. Он не доказывает
аэродинамическую точность, не заменяет анализ полной расчётной серии и не
разрешает физику вязкого отрыва или транзвука.

## 1. Входной контракт

### 1.1. MASTER

MASTER — окончательный `.vsp3`. При запуске сохраняются обычный и канонический
SHA-256, размер и `frozen_master.vsp3`. Исходный файл проверяется повторно в
конце. Все технические изменения выполняются только в расчётных двойниках.

Любое изменение формы, имён, Sets или параметров MASTER после сертификации
требует нового сертификата.

### 1.2. Имена и Sets

| База имени | Назначение | Пользовательский Set |
|---|---|---:|
| `Wing` | основное крыло, OpenVSP `Wing` | `Set_2` |
| `Fuselage` | основной фюзеляж | `Set_1` |
| `GO*` | горизонтальное оперение, OpenVSP `Wing` | `Set_2` |
| `VO*` | вертикальное оперение, OpenVSP `Wing` | `Set_2` |
| `Gondola*` | мотогондолы | `Set_1` |

`Wing` и `Fuselage` обязательны как точные единственные имена. Повторные
детали используют суффикс, например `VO_upper`, `Gondola_L`. В API OpenVSP
пользовательские `Set_1`/`Set_2` имеют индексы 4/5. Неизвестная роль не
угадывается, одинаковое точное имя неоднозначно.

Однозначную ошибку Set можно исправить в двойнике. Ошибочный тип тонкой
поверхности, пустой/пересекающийся состав или неоднозначность являются
blocker.

### 1.3. Опорные величины и область

Сертификат связывает:

- `reference.area` — `Sref`;
- `reference.cref` — САХ/продольную опорную длину;
- `reference.bref` — размах/поперечную опорную длину;
- `reference.center` — `[CG X, CG Y, CG Z]`;
- интервалы Mach, диапазон alpha, `beta` и положение GO.

Все значения должны быть конечными и согласованы с единицами VSP3. Базовая
область: `M=0,0…0,8` и `1,2…2,2`, `alpha=0…5°`, `beta=0°`, `GO=0°`.

### 1.4. Aliases и исключения

Проектные правила задаются в
`project_config.json → geometry_certification → policy_overrides`:

```json
{
  "semantics": {
    "aliases": {"VentralVO": "VO"},
    "declared_exclusions": [
      {
        "component": "AuxiliaryBody",
        "backends": ["vspaero", "hybrid"],
        "reason": "служебная поверхность, не часть физической модели",
        "replacement_required": ["not_physical"]
      }
    ]
  }
}
```

Каждое исключение обязано:

1. ссылаться на ровно один существующий компонент по точному имени;
2. иметь ровно `backends: ["vspaero", "hybrid"]`;
3. содержать непустую причину;
4. иметь непустой канонический список `replacement_required` из
   `machline_pressure_wave_all_points`, `parasite_drag_subsonic` либо
   единственного `not_physical`.

Старое поле `backend`, строка вместо списка, повторы, неподдерживаемое значение
или смешение `not_physical` с физическим источником отклоняются. Декларация
делается до просмотра эталона и не служит способом спрятать ошибку модели.

## 2. Запуск

1. Запустите `RepairMach.bat` и `[1] Проверить среду`.
2. Выберите проект и перепроверьте опоры.
3. Откройте `[9] Готовые сценарии`.
4. Выберите `[13] Автоматическая сертификация геометрии VSP3`.
5. Укажите окончательный MASTER.
6. На запрос TRI обычно нажмите Enter. RepairMach сам экспортирует TRI для
   MachLine из собственного Fine-двойника. Указанный старый TRI сохраняется
   только как audit hint и не становится авторитетным источником.
7. Дождитесь `certificate.json` и `certificate.md`.

Результаты находятся в `projects\<проект>\11_geometry_certification`. Каждый
запуск получает отдельный каталог. Успешный указатель —
`latest_certificate.json`, неудачный — `latest_failed_certificate.json`.

`run_vspaero_probes=false` создаёт диагностический пакет, но не даёт
solver-eligible сертификат.

## 3. Шлюзы G0–G8

### G0 — регистрация и заморозка

Фиксируются MASTER, опоры, область, эффективная политика, время и SHA-256.
Создаётся `source_manifest.json` и проверенная замороженная копия.

### G1 — инвентаризация и семантика

OpenVSP через `vspscript.exe` перечитывает все компоненты, типы, Sets,
секции, доступные параметры и координатные границы. Выполняется строгая
проверка имён, aliases, обязательных деталей и исключений.

### G2 — нативная диагностика

Сохраняется состояние MASTER до исправлений. Недоступная метрика остаётся
`null`; программа не придумывает площадь, объём, зазор или топологию.

### G3 — запечатанный PLAN

`transformation_plan.json` содержит полный детерминированный список действий
и привязан к SHA-256 MASTER, политики, опор и области. Любое несовпадение до
APPLY блокирует процесс.

### G4 — независимые двойники

Создаются отдельные файлы:

- `vspaero_mixed`;
- `vspaero_lifting` с заведомо пустым thick-Set;
- `machline`;
- `parasite` — неизменённая полная копия.

Изменения одного backend не переносятся в другой и не возвращаются в MASTER.

### G5 — контролируемые действия

Разрешены только:

- однозначная коррекция Sets;
- очистка Sets у заранее объявленного исключения;
- замена практически нулевой концевой хорды на малую конечную в пределах 1%
  изменения площади;
- явно заданный offset точного компонента в пределах `0,002·cref`.

Каждое действие получает причину, старое/новое значение и целевые двойники.
Произвольное закрытие отверстий, перестройка профиля, изменение площади крыла
или подгонка к кривой запрещены.

### G6 — readback и дельты

Все двойники повторно открываются OpenVSP. RepairMach проверяет фактические
значения изменённых параметров, состав, геометрические отпечатки и бюджеты.
Неприменённое действие, неожиданный побочный сдвиг или нечитаемый файл
блокируют тракт.

### G7 — адаптивная сеточная лестница, 15 anchors и MachLine TRI

Для `vspaero_mixed`, `vspaero_lifting` и `machline` всегда строятся три
независимых уровня `Coarse`, `Medium`, `Fine`. Проверяются фактические значения
всех шести Tess-параметров; лестница должна строго возрастать, а подписи
уровней — различаться. `Fine` остаётся единственной производственной сеткой.

Если корректная точка лишь погранично не проходит сеточную проверку, программа
может автоматически добавить проверочный `ExtraFine`. Если после него все
последние изменения уже находятся внутри неизменных допусков, но сохраняется
значимая смена знака, выполняется последний арбитраж `UltraFine`. Эти уровни не
заменяют `Fine` в последующих расчётах и не расширяют область сертификата.

Полный профиль `full_anchor_envelope`:

| M | alpha |
|---:|---|
| 0,0 | 0°, 5° |
| 0,4 | 0°, 5° |
| 0,8 | 0°, 1°, 5° |
| 1,2 | 0°, 1°, 5° |
| 1,7 | 0°, 1°, 5° |
| 2,2 | 0°, 5° |

Это 15 anchors, и каждый запускается как минимум на Coarse, Medium и Fine. Для каждой
точки нужны полный POLAR/CSV/log, ровно запрошенная пара Mach/alpha, конечные
`CLtot`/`CDi`/`CDtot` и здоровое состояние решателя. Для любого `M > 0`
обязательна однозначная конечная невязка `log10(L2) <= -0.3`. Для строго
`M=0`, где VSPAERO 3.51 не выводит эту запись, разрешён только заранее
настроенный контроль по полной сеточной сходимости.

Единственное дополнительное исключение для журнала VSPAERO относится к
нормировке нулевой правой части: при точных `alpha=0`, `beta=0`, `CLtot=0`,
конечной итоговой невязке и отсутствии иных fatal-сигналов промежуточные
`Red: nan`/`Max: nan` считаются предупреждением
`zero_rhs_normalization_nan`. Любой NaN в коэффициентах, ненулевая подъёмная
сила или отсутствие конечной итоговой невязки по-прежнему блокируют точку.

Для `CLtot` и `CDtot` сохраняются знаковые шаги и проверяется Medium→Fine:

```text
delta_CM = Medium - Coarse
delta_MF = Fine - Medium
delta_rel = |Fine - Medium| / max(|Fine|, |Medium|, 1e-6).
contraction_ratio = |delta_MF| / |delta_CM|, если знаменатель значим.
```

Точка проходит при `delta_rel <= 0.05` либо при абсолютном отличии не более
`0,005` для `CLtot` и `0,0005` для `CDtot`. Большое Coarse→Medium само по себе
не является veto: численный допуск относится к Medium→Fine. Однако если оба
шага значимы относительно абсолютного допуска и имеют разные знаки,
последовательность помечается `oscillating`. Изменение меньше 10% абсолютного
допуска считается шумом ниже разрешения, но сами допуски 5%/0,005/0,0005 не
меняются. Значимая осцилляция блокирует базовую тройку и может быть разрешена
только следующей заранее заданной проверочной сеткой.
В `mesh_convergence` для каждой величины записываются `coarse_medium_delta`,
`medium_fine_delta`, относительные изменения, `monotonic`, `oscillating` и
`contraction_ratio`; общий список `oscillating_quantities` входит в диагноз.

При настоящем нечисловом отказе lifting-постановки сертификатор автоматически
повторяет только проблемный режим на диагностических двойниках, по одному
исключая семантические группы `GO*`, `VO*` и другие допустимые тонкие группы.
В отчёте сохраняются группа, исключённые детали и факт восстановления конечного
решения. Диагностический двойник никогда не становится расчётной геометрией и
не может получить допуск; результат служит адресным заданием для ремонта
MASTER и его повторной сертификации.

При наличии одной или нескольких `Gondola*` сверхзвуковые anchors с
`engine_boundary: auto` применяют `To Face` ко всем распознанным гондолам.
Без гондолы используется исходная boundary-постановка.

Если mixed не прошёл, разрешён fallback к lifting-only. Успех lifting не
выдаётся за полный самолёт: исключённые толстые тела записываются в сертификат,
а гибрид должен восстановить MachLine pressure/wave на всех точках и Parasite
Drag на всех дозвуковых Mach.

MachLine TRI создаётся автоматически командой OpenVSP `EXPORT_NASCART` из
Fine-двойника. Запечатываются:

- SHA-256 MASTER и PLAN;
- SHA-256 базового и Fine MachLine-двойника;
- фактическая mesh signature;
- thick/thin Set bindings;
- формат экспорта, путь и SHA-256 TRI;
- путь и SHA-256 `vspscript.exe`;
- fingerprint всей записи экспорта.

Подмена Fine VSP3, TRI, Sets, mesh signature или record fingerprint приводит
к `GEO-TRI-LINEAGE-001`; произвольный внешний TRI отклоняется до чтения.

После lineage-проверки анализируются индексы, повторы, вырожденные панели,
неманифолдные рёбра, ориентация и Mach-критерий. Ремонт ограничен меньшим из
100 панелей и 0,5% сетки; хорошие панели нельзя терять. Автоматическое
смещение вершин выключено.

### G8 — выпуск сертификата

`certificate.json` имеет схему `repairmach.geometry-certificate/1.1`,
собственный fingerprint и ID `RMC-...`. Он содержит доказательства, findings,
преобразования, сетки, anchors, программные отпечатки, backend eligibility,
qualified scope и scenario eligibility. Для каждого допускаемого сценария
записывается `scenario_sha256` канонического полного словаря сценария. Ручное
редактирование нарушает целостность.

## 4. Вердикты и backend eligibility

| Вердикт | Значение |
|---|---|
| `PASS_NATIVE` | mixed-постановка прошла без регуляризации |
| `PASS_REGULARIZED` | mixed прошла после разрешённых малых действий |
| `PASS_WITH_DECLARED_EXCLUSIONS` | пригоден ограниченный тракт; замещение обязательно |
| `FAIL` | есть blocker, нарушен бюджет/lineage или отсутствует квалификация |

Не ограничивайтесь общим вердиктом. Проверяйте:

- `backends.vspaero.eligible` и `mode`;
- `backends.machline.eligible` и точный `certified_mesh.tri`;
- `backends.parasite_drag.eligible`;
- `backends.hybrid.eligible` или `conditional`;
- `qualified_scope` и `eligible_scenarios`;
- `software.solvers.*.sha256`;
- `flags.full_geometry_represented` и
  `flags.hybrid_substitution_required`.

MachLine-ошибка не обязана аннулировать независимо пригодный VSPAERO backend,
но запрещает использовать MachLine в строгом гибриде. `FAIL` нельзя обходить.

## 5. Использование сертификата в расчёте

При запуске готового VSPAERO-сценария RepairMach ищет последний сертификат.
Если сертификат относится к выбранному MASTER, программа проверяет его
целостность и соответствие сценарию. Сравниваются ID и SHA-256 актуального
полного словаря с запечатанным `scenario_sha256`; изменение cases, GO, beta,
`engine_boundary` или другого поля под прежним ID требует пересертификации.
Непригодность блокирует запуск; пригодный сертификат автоматически направляет
расчёт на записанный Fine-двойник и фиксирует опоры из сертификата.

Интерактивный диапазон VSPAERO из пункта `[8]` намеренно не получает
`certificate_binding`, даже если сертификат того же MASTER существует. Он
считается непосредственно на выбранном MASTER с меткой
`НЕСЕРТИФИЦИРОВАННЫЙ ЗАПУСК`, потому что его Mach/alpha/GO не были запечатаны
как неизменный сценарий.

Для MachLine используйте только `backends.machline.solver_geometry.path`.
Для Parasite Drag пункт `[10]` также выбирает собственный сертифицированный
двойник. Каждый producer-manifest сохраняет SHA-256 расчётной геометрии,
выходов и реально запущенных executable. Гибридный потребитель повторно
считает эти отпечатки и качество выходов. Для VSPAERO эффективный предел
невязки равен более строгому из `-0.3` и значения producer-manifest: значение
выше `-0.3` не может ослабить методику.

Для Parasite Drag гибрид проверяет печать producer-manifest, фактические
SHA-256 script, log, CSV, `vspscript.exe`, MASTER и solver VSP3. Модель,
GeomSet, Mach и Sref читаются также из реального script; переименование CSV,
подмена файла или изменение описательных полей не заменяют эту проверку.

При `PASS_WITH_DECLARED_EXCLUSIONS` строгая сборка дополнительно требует
`replacement_coverage`. В режиме `auto` оно создаётся только из фактически
использованных запечатанных отчётов. Для физического компонента необходимы
MachLine для каждой строки и Parasite Drag для каждого дозвукового Mach;
`not_physical` допустим только при такой декларации в сертификате.

## 6. Что сертификат намеренно не делает

- не выбирает вариант по близости к продувке;
- не исправляет аэродинамическую форму и опорные величины;
- не закрывает отверстия и не перестраивает неманифолдную область произвольно;
- не балансирует самолёт по `Cm=0`;
- не доказывает переносимость полуэмпирики;
- не моделирует вязко-ударное взаимодействие, отрыв и реальную структуру
  скачков;
- не превращает численный допуск 5% в обещание 5% относительно эксперимента.

## 7. Типовые blockers

| Код/симптом | Действие |
|---|---|
| `GEO-NAME-001` | исправить имя или объявить единственный alias |
| `GEO-EXCL-002` | сопоставить исключение ровно одному компоненту |
| `GEO-REF-001` | исправить `Sref`, `cref`, `bref`, CG |
| `GEO-SET-001/002` | исправить роль/тип/Set; не угадывать назначение |
| `GEO-TIP-002` | инженерно исправить законцовку MASTER |
| `GEO-INT-002` | исправить неоднозначный или чрезмерный offset |
| `GEO-MESH-001/002` | исправить фактическую лестницу Tess |
| VSPAERO output validation | восстановить точную сетку режимов и невязку `<= -0.3` |
| Medium→Fine > 5% и выше abs допуска | уточнить сетку, не смотреть эталон |
| `oscillating=true` | дождаться автоматического ExtraFine/UltraFine; при сохранении значимой осцилляции исправить сетку или постановку |
| `failure_diagnostics` указывает группу | проверить форму, пересечения, Sets и сопряжения этой группы в MASTER; не использовать диагностический двойник для выпуска |
| `GEO-TRI-LINEAGE-001` | заново экспортировать TRI текущего Fine-двойника |
| `GEO-TRI-001/002` | исправить топологию в источнике или сеточной политике |
| `GEO-MACH-001` | перестроить панели; не смещать вершины ради формального PASS |
| `MASTER changed` | прекратить использование и запустить новую сертификацию |

## 8. Граница методики

Автоматизированы G0–G8, 15 anchors × 3 базовых уровня с условными
ExtraFine/UltraFine, автоматическая локализация отказавшей компонентной группы,
автоматический Fine TRI,
backend-specific сертификат, строгие producer/consumer hashes, гибридная
сборка и проверяемый Excel.

Сценарии «Сеточная сходимость», «Ночной точный расчёт» и «Верификация» в
каталоге пока имеют статус `ПРОТОКОЛ`: они фиксируют воспроизводимое задание,
но не выдают подготовленный манифест за выполненную полную очередь. Полный
GCI, автоматическая балансировка `Cm=0` и высокоточная вязкая CFD-физика
остаются отдельными этапами.
