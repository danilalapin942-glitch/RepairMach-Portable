# RepairMach Portable

RepairMach 9.1 — Windows-оболочка для подготовки сеток и совместной работы с MachLine, OpenVSP и VSPAERO.

> Статус: экспериментальная beta-версия. Расчётные результаты необходимо проверять по сходимости, распределению давления и независимым данным.

## Возможности

- переносимый Python runtime;
- локальный запуск MachLine без установленного компилятора;
- создание структуры расчётного проекта;
- автоматическая диагностика TRI сразу после импорта;
- консервативное исправление дубликатов, вырожденных панелей и ориентации;
- проверка панелей по сверхзвуковому Mach-критерию и подтверждаемая автоправка вершин;
- отдельное сохранение исходника, исправленной сетки и JSON-отчётов;
- подготовка JSON-файлов MachLine;
- запуск MachLine с сохранением консольного журнала;
- обнаружение установленного OpenVSP/VSPAERO;
- импорт `.vsp3` внутрь выбранного проекта и автоматический запуск расчёта VSPAERO;
- обязательная проверка принятого деления модели: `Set_1` — фюзеляж и мотогондолы, `Set_2` — крыло и оперение;
- стандартная функция `[9]`: `alpha=0…5°` с шагом `1°` и выбор дозвукового, сверхзвукового либо объединённого диапазона Mach;
- версионированный каталог готовых расчётных сценариев в функции `[9]`;
- исполняемые сценарии диагностики TRI, быстрой оценки, дозвуковой, сверхзвуковой и полной АДХ, а также расчёта с заданным углом `GO`;
- воспроизводимые протоколы сеточной сходимости, ночного гибридного расчёта и верификации;
- контроль имён `Wing`, `Fuselage`, `GO`, `VO`, `Gondola` и их принадлежности к `Set_1`/`Set_2`;
- необязательный заданный балансировочный угол горизонтального оперения с выбором геометрии по точному имени;
- запуск сценариев `.vspscript` с сохранением журнала;
- компонентный расчёт OpenVSP Parasite Drag с сохранением `Cf`, форм-фактора, `Q`, смоченной площади и вклада каждого элемента;
- чтение поляр VSPAERO и выбор точки с теми же `Mach` и углом атаки, что и в отчёте MachLine;
- гибридный JSON-отчёт без калибровочной константы, с раздельными слагаемыми сопротивления и предупреждениями об области применимости;
- комплект TRI-моделей и примеров JSON;
- резервная исходная версия и диагностическая сборка MachLine.

## Быстрый запуск

1. Распакуйте проект в каталог с коротким путём без системных ограничений доступа.
2. Запустите `RepairMach.bat`.
3. В меню выберите проверку среды.
4. Создайте или выберите проект.
5. Импортируйте TRI и изучите отчёт диагностики.
6. Подготовьте JSON и запустите MachLine.
7. Для стандартного исследования выберите функцию `[9]`, затем готовый сценарий и импортируйте VSP3.
8. Выберите быструю оценку, дозвуковую, сверхзвуковую или полную АДХ. Стандартный шаг Mach равен `0,1`, а углы атаки заданы как `0…5°` с шагом `1°`.
9. При необходимости включите заданный балансировочный угол ГО, укажите точное имя геометрии (для МиГ-29 — `GO`) и абсолютный угол установки в градусах.
10. После проверки `Set_1`/`Set_2` и геометрии ГО программа сама запустит VSPAERO и сохранит POLAR, CSV, лог и манифест запуска.
11. Ручной диапазон остаётся в функции `[8]`; прямой запуск `.vspscript` находится в расширенной функции `[13]`.
12. Для дозвуковой точки выполните Parasite Drag и соберите гибридный отчёт.

Для прямого запуска движка используйте:

```text
engines\MachLine\run_machline.bat
```

```text

projects/MiG_29/      TRI-модели и JSON
runtime/python/       переносимый Python

```

## Важные замечания

- MachLine является линейным панельным методом и не заменяет вязкий CFD-расчёт.
- OpenVSP устанавливается отдельно; его локальный путь задаётся в `config/repairmach_settings.json`.
- В интерфейсе OpenVSP пользовательский `Set_1` имеет API-индекс 4, а `Set_2` — индекс 5: RepairMach выполняет это преобразование автоматически.
- Перед VSPAERO все аэродинамические детали должны принадлежать ровно одному из двух наборов. `Set_1` допускает Fuselage/Stack/Pod и другие объёмные детали; `Set_2` предназначен только для геометрий типа Wing.
- В готовых сценариях 9.1 обязательны точные базовые имена `Wing` и `Fuselage`. `GO`, `VO` и `Gondola` используются для соответствующих компонентов; повторные элементы могут иметь суффиксы, например `VO_R` или `Gondola_L`.
- Расчёт не запускается, если набор пуст, одна деталь находится в обоих наборах, деталь не размечена или тип детали не соответствует назначению набора.
- Режим «всё вместе» запускает два отдельных расчёта и не создаёт точки `M=0,9` и `M=1,0`; это не смешивает дозвуковой и сверхзвуковой диапазоны через переходную область.
- Угол ГО задаётся как абсолютный `Y_Rel_Rotation` рабочей копии VSP3. Исходный импортированный файл не изменяется.
- Эта функция применяет известный угол установки. Она не выполняет автоматическую балансировку по условию `Cm=0`; поиск такого угла требует отдельного итерационного расчёта.
- В RepairMach 9 OpenVSP Parasite Drag разрешён только при `0 < Mach < 1`, поскольку этот расчёт документирован как дозвуковой.
- Добавление `VSPAERO CDi` к MachLine с активным следом может частично дважды учитывать индуктивное сопротивление; программа явно записывает это предупреждение в отчёт.
- Число `0.01828` и другие книжные подгоночные добавки в версии 9 не используются.
- Перед использованием коэффициентов проверяйте остаточную ошибку решателя.
- Для коэффициентов момента необходимо корректно задать `reference.length` и `reference.CG`.
- При создании каждого MachLine JSON версия 9 повторно показывает `Sref`, САХ и координаты центра масс; для нового самолёта нельзя оставлять значения проекта MiG-29.
- Старые JSON с абсолютными путями `C:\RepairMach` сохранены как исходные данные; для другого компьютера используйте переносимые копии либо создайте JSON заново через RepairMach.
- Автоматическое исправление намеренно не закрывает отверстия и не перестраивает неманифолдные зоны: такие изменения требуют контроля геометрии.
- Сценарии, отмеченные как `ПРОТОКОЛ`, в 9.1 создают версионированный манифест, но не выдаются за выполненный расчёт. Автоматическая генерация трёх CFD-сеток и единая очередь MachLine+VSPAERO остаются следующим этапом.
